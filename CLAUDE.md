# Overlay Browser

Electron app for Windows, Linux (X11) and macOS: an overlay browser, always on top, shown/hidden with a global shortcut (`platform.defaultShortcut`: Win/Super+F10, Cmd+Shift+Space on macOS) or from the notification area icon. Meant for browsing sites (wikis, calculators) while playing.

- `main.js`: window, preferences (`userData/prefs.json`: `%APPDATA%\overlay-browser` on Windows, `~/.config/overlay-browser` on Linux, `~/Library/Application Support/overlay-browser` on macOS), tray, shortcut (globalShortcut + `uiohook-napi` hook, required in game). Site popups (`<webview allowpopups>`): what a browser opens in a tab (`target=_blank` links, `window.open` without window features, Ctrl/middle click: `disposition` `foreground-tab`/`background-tab`) is denied and sent to the page (`site:open`), which shows it in the current list's tab of the same site (same host; the opener's tab first) or asks whether to add it as a new site (`openSiteUrl`); explicit windows (`window.open` with features: logins such as "Continue with Google", which need `window.opener`) open as child windows of the overlay, always on top; for the hide on blur the overlay and its popups count as one window (focus moving between them is not a blur, `overlayFocused`), the popups are hidden and shown again with the overlay (`hiddenPopups`), and when one closes the overlay takes the focus back. User agent without the `Electron/` and app tokens (`app.userAgentFallback`), otherwise Google refuses the login. Contains no OS-specific code: it goes through `platform/`.
- `platform/`: one module per OS behind a common interface (described in `platform/index.js`). Each module declares its `features` (keyboardHook, focusRestore, edgeSnap, appDetect) and how translucency is obtained (`opacity`: native/css/none); `bookmarkStores` lists the browsers' data folders for the bookmark import (folders the system does not let the app read are reported as denied; none on macOS, which would need Full Disk Access: there bookmarks are imported from an exported HTML file only); `memoryUsage` measures the memory of each process (private bytes on Windows, PSS from `/proc` on Linux, physical footprint on macOS, working set otherwise), shown on the Settings page.
  - `win32.js`: focus, edge snapping and foreground app detection (executable, application name from its version information: `ProductName`, or `FileDescription` for Windows' own programs; window title) via Win32 API (`koffi`).
  - `linux.js`: X11 only (forces `ozone-platform=x11`); focus via `_NET_ACTIVE_WINDOW` through libX11 (`koffi`); foreground app from the window properties (`WM_CLASS`, `_NET_WM_PID`) and `/proc` (Wine/Proton `.exe`, Steam AppID); opacity via CSS on a transparent window; no edge snapping.
  - `darwin.js`: the window is a non-activating panel (`windowOptions: { type: 'panel' }`): it takes the keyboard without activating the app and shows over fullscreen apps; no Dock icon (`LSUIElement`), Edit-only app menu; no keyboard hook (globalShortcut suffices, uiohook would need the Accessibility permission); foreground app from `NSWorkspace.frontmostApplication` via the Objective-C runtime (`koffi`), app name as title; memory from `proc_pid_rusage`; menu bar icon resized by `trayImage`.
  - `generic.js`: Electron only; base of the other modules and fallback for systems without a module.
- Site lists (`prefs.lists`): one per application, matched on the normalized executable (`{ exe }`; `{ title }` if unknown; `null` = general list, used when nothing is detected, always present and not removable), created only when the first site is added; named after the application (`foregroundApp().name`, else the window title; lists named after a window title are renamed once the app name is known, except predefined ones, `renameContextList`). The current list is the one chosen by hand (`prefs.pinnedList`) or else the one of the app the overlay was opened over (`foregroundApp()`, sent by `main.js` at every show). The old single list (`sites`) is migrated to the general list, without the sites of the predefined lists.
- `bookmarks.js`: bookmark import (read-only) and export. Sources: one per browser profile, from the folders given by `platform.bookmarkStores()` (Chromium browsers: `Bookmarks` JSON + profile names from `Local State`, Opera also with its Speed Dials and other `custom_root` folders; Firefox and derivatives: `profiles.ini` + `places.sqlite`, read from a temporary copy with its `-wal` through `node:sqlite`, so it works with Firefox open), or an HTML file in the Netscape format chosen with the system dialog (`bookmarks:file`; the overlay does not hide on blur while it is open, `fileDialogOpen`). Returns a tree of folders (`root`: bar/menu/other/mobile) and http(s) bookmarks. The page imports from the add dialog (`openAddDialog`): from the "+" in the bar with the Address and Bookmarks tabs, into the current list; from "Import bookmarks…" in the Bookmarks section at the end of the Home (`home`), bookmarks only, into a list chosen in the dialog (the current one at first): tree with checkboxes, search, addresses already in the list not selectable, selection by address (`addSites` skips duplicates). Export (`openExportDialog`, "Export bookmarks…" in the same section): the same tree component (`treePicker`) with one folder per list and its sites, all selected at first, plus an "all bookmarks" checkbox; saved by `main.js` (`bookmarks:export`, system save dialog) as a Netscape HTML file with one folder per list (`toHtml`).
- `lists/`: predefined lists shipped with the app (`index.json` maps executables to files, see `lists/README.md`); loaded automatically the first time the overlay is opened over an app that has no list yet (`prefs.presetsApplied`), then only offered on the Home if that list is removed.
- `index.html`: Home with all site lists (current one first, others collapsible; edit sites, use a list, remove a list), tabs of the current list (one `<webview>` per site, created when its tab is first opened; pages not in use, i.e. all but the active tab of the visible overlay (`win:visible` sent by `main.js`), are each closed after some minutes without use, whatever their list, 5–60: `settings.unloadAfter` (until 1.0 there were two delays, the current list's `unloadCurrentAfter` is migrated to it), `sweepPages`; a closed page loads again from the last address visited (`lastUrls`, kept in memory only); a list always opens on its last tab (`activeTab`: a site id, `':home'` or `':settings'`), its page reopened if it was closed, `showCurrentList`; tabs and Home site rows reordered by dragging, `makeSortable`), settings (including window opacity, `settings.opacity`, applied by the page via CSS when `state.platform.opacity === 'css'`, natively by `main.js` otherwise, hidden when `'none'`; accent color, `settings.accent`, a name from the predefined palette: names validated in `main.js` (`ACCENTS`), colors in the page (`ACCENT_COLORS`, CSS variables `--accent`/`--accent-text`); next to the title, the app version, `app.getVersion()` sent by `main.js`, and the GitHub link, `REPO_URL`, opened in the system browser).
- `locales/*.json`: UI texts, one file per language (code = file name); read by `main.js` and passed to the page. Language: user setting, else first available system language, else English.
- `preload.js`: IPC bridge between the page and the main process.
- Build: `npm run dist` (electron-builder, packages for the current OS, unsigned) into `dist/`; `dist:win` (NSIS installer + portable), `dist:store` (unsigned AppX for the Microsoft Store, signed by the Store on submission; tiles in `build/appx/`; built by the manual `store.yml` workflow; the Store version's `userData` is redirected under `%LOCALAPPDATA%\Packages\…`), `dist:linux` (AppImage, built on Linux); `dist:mac` (DMG arm64 + x64, ad-hoc signed, built on macOS; icon `build/icon-mac.png`, 512 px).

## Branches and releases

- `release/<major.minor>` (now `release/1.0`): fixes and small polish for the version being released. Release tags (`v1.0.0-beta.2`, `v1.0.0`, `v1.0.1`…) are created here; the release workflow runs on any `v*` tag, whatever the branch.
- `main`: development of the next version (now 1.1: e.g. bookmark import/export). New features go on `feature/<name>` branches from `main`, merged back into `main`.
- A fix for the released version is always made on the release branch, then the release branch is merged into `main` (`git merge release/1.0`); never merge `main` into a release branch or cherry-pick features into it.
- Before working, check which branch is checked out and whether the change is a fix (release branch) or a feature (`main`/feature branch); ask if unclear.
- When the next version is ready for beta, create `release/<next>` from `main`.
