# Overlay Browser

Electron app for Windows, Linux (X11) and macOS: an overlay browser, always on top, shown/hidden with a global shortcut (`platform.defaultShortcut`: Win/Super+F10, Cmd+Shift+Space on macOS) or from the notification area icon. Meant for browsing sites (wikis, calculators) while playing.

- `main.js`: window, preferences (`userData/prefs.json`: `%APPDATA%\overlay-browser` on Windows, `~/.config/overlay-browser` on Linux, `~/Library/Application Support/overlay-browser` on macOS), tray, shortcut (globalShortcut + `uiohook-napi` hook, required in game). Site popups (`<webview allowpopups>`: logins such as "Continue with Google", `target=_blank` links) open as child windows of the overlay, always on top; while one is visible the overlay does not hide on blur. User agent without the `Electron/` and app tokens (`app.userAgentFallback`), otherwise Google refuses the login. Contains no OS-specific code: it goes through `platform/`.
- `platform/`: one module per OS behind a common interface (described in `platform/index.js`). Each module declares its `features` (keyboardHook, focusRestore, edgeSnap, appDetect) and how translucency is obtained (`opacity`: native/css/none); `memoryUsage` measures the memory of each process (private bytes on Windows, PSS from `/proc` on Linux, physical footprint on macOS, working set otherwise), shown on the Settings page.
  - `win32.js`: focus, edge snapping and foreground app detection (executable, application name from its version information: `ProductName`, or `FileDescription` for Windows' own programs; window title) via Win32 API (`koffi`).
  - `linux.js`: X11 only (forces `ozone-platform=x11`); focus via `_NET_ACTIVE_WINDOW` through libX11 (`koffi`); foreground app from the window properties (`WM_CLASS`, `_NET_WM_PID`) and `/proc` (Wine/Proton `.exe`, Steam AppID); opacity via CSS on a transparent window; no edge snapping.
  - `darwin.js`: the window is a non-activating panel (`windowOptions: { type: 'panel' }`): it takes the keyboard without activating the app and shows over fullscreen apps; no Dock icon (`LSUIElement`), Edit-only app menu; no keyboard hook (globalShortcut suffices, uiohook would need the Accessibility permission); foreground app from `NSWorkspace.frontmostApplication` via the Objective-C runtime (`koffi`), app name as title; memory from `proc_pid_rusage`; menu bar icon resized by `trayImage`.
  - `generic.js`: Electron only; base of the other modules and fallback for systems without a module.
- Site lists (`prefs.lists`): one per application, matched on the normalized executable (`{ exe }`; `{ title }` if unknown; `null` = general list, used when nothing is detected, always present and not removable), created only when the first site is added; named after the application (`foregroundApp().name`, else the window title; lists named after a window title are renamed once the app name is known, except predefined ones, `renameContextList`). The current list is the one chosen by hand (`prefs.pinnedList`) or else the one of the app the overlay was opened over (`foregroundApp()`, sent by `main.js` at every show). The old single list (`sites`) is migrated to the general list, without the sites of the predefined lists.
- `lists/`: predefined lists shipped with the app (`index.json` maps executables to files, see `lists/README.md`); loaded automatically the first time the overlay is opened over an app that has no list yet (`prefs.presetsApplied`), then only offered on the Home if that list is removed.
- `index.html`: Home with all site lists (current one first, others collapsible; edit sites, use a list, remove a list), tabs of the current list (one `<webview>` per site, created when its tab is first opened; those not in the current list are closed after `settings.unloadAfter` minutes, 5–60, `sweepPages`; tabs and Home site rows reordered by dragging, `makeSortable`), settings (including window opacity, `settings.opacity`, applied by the page via CSS when `state.platform.opacity === 'css'`, natively by `main.js` otherwise, hidden when `'none'`; accent color, `settings.accent`, a name from the predefined palette: names validated in `main.js` (`ACCENTS`), colors in the page (`ACCENT_COLORS`, CSS variables `--accent`/`--accent-text`); next to the title, the app version, `app.getVersion()` sent by `main.js`, and the GitHub link, `REPO_URL`, opened in the system browser).
- `locales/*.json`: UI texts, one file per language (code = file name); read by `main.js` and passed to the page. Language: user setting, else first available system language, else English.
- `preload.js`: IPC bridge between the page and the main process.
- Build: `npm run dist` (electron-builder, packages for the current OS, unsigned) into `dist/`; `dist:win` (NSIS installer + portable), `dist:linux` (AppImage, built on Linux); `dist:mac` (DMG arm64 + x64, ad-hoc signed, built on macOS; icon `build/icon-mac.png`, 512 px).

## Branches and releases

- `release/<major.minor>` (now `release/1.0`): fixes and small polish for the version being released. Release tags (`v1.0.0-beta.2`, `v1.0.0`, `v1.0.1`…) are created here; the release workflow runs on any `v*` tag, whatever the branch.
- `main`: development of the next version (now 1.1: e.g. bookmark import/export). New features go on `feature/<name>` branches from `main`, merged back into `main`.
- A fix for the released version is always made on the release branch, then the release branch is merged into `main` (`git merge release/1.0`); never merge `main` into a release branch or cherry-pick features into it.
- Before working, check which branch is checked out and whether the change is a fix (release branch) or a feature (`main`/feature branch); ask if unclear.
- When the next version is ready for beta, create `release/<next>` from `main`.
