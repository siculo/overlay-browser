# Overlay Browser

Electron app for Windows, Linux (X11) and macOS: an overlay browser, always on top, shown/hidden with a global shortcut (`platform.defaultShortcut`: Win/Super+F10, Cmd+Shift+Space on macOS) or from the notification area icon. Meant for browsing sites (wikis, calculators) while playing.

- `main.js`: window, preferences (`userData/prefs.json`: `%APPDATA%\overlay-browser` on Windows, `~/.config/overlay-browser` on Linux, `~/Library/Application Support/overlay-browser` on macOS), tray (menu: Show/Hide, Home, Settings, the "hide when it loses focus" option as a checkbox, `settings.hideOnBlur`, the same as on the Settings page, which is told of the change, `settings:changed`; Quit), shortcut (globalShortcut + `uiohook-napi` hook, required in game). Site popups (`<webview allowpopups>`): what a browser opens in a tab (`target=_blank` links, `window.open` without window features, Ctrl/middle click: `disposition` `foreground-tab`/`background-tab`) is denied and sent to the page (`site:open`), which shows it in the current list's tab of the same site (same host; the opener's tab first) or asks whether to add it as a new site (`openSiteUrl`); explicit windows (`window.open` with features: logins such as "Continue with Google", which need `window.opener`) open as child windows of the overlay, always on top; for the hide on blur the overlay and its popups count as one window (focus moving between them is not a blur, `overlayFocused`), the popups are hidden and shown again with the overlay (`hiddenPopups`), and when one closes the overlay takes the focus back. New versions: the GitHub releases (`RELEASES_API`) are checked 10 s after startup and then every 6 hours (`checkForUpdate`, `settings.checkUpdates`, Settings, Behavior section; not in the Store version, `process.windowsStore`: option hidden); prereleases count only when the running version is a prerelease; the newer version is sent to the page (`update:available`), which shows it next to the app version on the Settings page (`#app-update`, a link to the release page) and as a strip below the navigation bar (`#update`) with a button opening the release page in the system browser (`update:open`) and a close button (`update:dismiss`, `prefs.updateDismissed`: the strip is not shown again for that version, the Settings page still shows it). Context menu of text (`context-menu`): in the text fields (`isEditable`; overlay page, site pages and their popups) Undo, Redo, Cut, Copy, Paste, Select All; on text that cannot be edited Copy and Select All only, anywhere in the site pages and their popups, in the overlay page only on a read-only text field (`formControlType`, the address of a site's tab) or a selection; on a link of the site pages, first Open link in new tab (http(s) only; `site:openNew`: the page asks whether to add it as a new tab of the current list, after the tab it comes from, and does nothing if refused; a tab already on that address is shown instead, `openLinkInNewTab`) and Copy link; on an image (`mediaType`, `hasImageContents`) Copy image (`copyImageAt`), after the link items; acting on the clicked page, enabled from `editFlags`, labels `edit.*` in the locales. User agent without the `Electron/` and app tokens (`app.userAgentFallback`), otherwise Google refuses the login; the site pages and their popups also get the Client Hints of Chrome, which Google checks as well: `Sec-CH-UA*` headers with the "Google Chrome" brand on every https request (Electron sends none; `setupClientHints`) and, in the http(s) pages, `navigator.userAgentData` with that brand and `window.chrome` with `app`/`csi`/`loadTimes` (`chrome-hints.js`, session preload run in the page's world). Diagnostic log `userData/overlay.log`: only what happens in the app, never the keys pressed nor anything about the browsing (no addresses or page titles: sites by position in their list, lists by application, address settings as set/empty). Errors and crashes always (`logError`, preceded once per session by the `session` line, start time, version, platform, and the current settings); with the detailed log, `settings.verboseLog` (Settings, Diagnostics section, with buttons to show the file and to empty it, `log:clear`, after a confirmation), also what happens (`log`): startup, shortcut source (hook/globalShortcut), shows and hides with the foreground state, blur, foreground app, and the user's actions (`ui:` lines: tabs, sites and lists added/removed/reordered, Pin, predefined lists, settings, shortcut, bookmark import (add dialog opened/confirmed/cancelled, sources found, source or file read with its number of bookmarks) and export; from the page through `logAction`, `log:action`), and the memory (`memory:` lines, `logMemory`, `log:memory`: total as on the Settings page, processes, open site pages) when a page is first loaded and after pages are closed for inactivity. Contains no OS-specific code: it goes through `platform/`.
- `platform/`: one module per OS behind a common interface (described in `platform/index.js`). The notification area icon (`trayImage`) is `assets/icon-16.png` (simplified drawing) at scale 1 and `assets/icon.png` (32 px) at scale 2 (Windows, macOS menu bar), the 32 px one alone on Linux. Icons generated from the drawing at each size: `build/icon.ico` (Windows, 16–256 px), `build/icon.png`, `build/icon-mac.png`, `build/appx/`. Each module declares its `features` (keyboardHook, focusRestore, edgeSnap, appDetect) and how translucency is obtained (`opacity`: native/css/none); `bookmarkStores` lists the browsers' data folders for the bookmark import (folders the system does not let the app read are reported as denied; none on macOS, which would need Full Disk Access: there bookmarks are imported from an exported HTML file only); `memoryUsage` measures the memory of each process (private bytes on Windows, PSS from `/proc` on Linux, physical footprint on macOS, working set otherwise), shown on the Settings page.
  - `win32.js`: focus, edge snapping and foreground app detection (executable, application name from its version information: `ProductName`, or `FileDescription` for Windows' own programs; window title) via Win32 API (`koffi`).
  - `linux.js`: X11 only (forces `ozone-platform=x11`); focus via `_NET_ACTIVE_WINDOW` through libX11 (`koffi`); foreground app from the window properties (`WM_CLASS`, `_NET_WM_PID`) and `/proc` (Wine/Proton `.exe`, Steam AppID); opacity via CSS on a transparent window; no edge snapping.
  - `darwin.js`: the window is a non-activating panel (`windowOptions: { type: 'panel' }`): it takes the keyboard without activating the app and shows over fullscreen apps; always-on-top level just below the menus (`topLevel`: `pop-up-menu` -1, elsewhere `screen-saver`; used for the overlay and its popups), so the menu bar's menus open over it; no Dock icon (`LSUIElement`), Edit-only app menu; no keyboard hook (globalShortcut suffices, uiohook would need the Accessibility permission); foreground app from `NSWorkspace.frontmostApplication` via the Objective-C runtime (`koffi`), app name as title; memory from `proc_pid_rusage`.
  - `generic.js`: Electron only; base of the other modules and fallback for systems without a module.
  - `hosted.js`: applications run by a runtime (Java: `java`/`javaw`, whose name would be "OpenJDK Platform" for all of them), told apart by their command line (read only for the runtimes: `NtQueryInformationProcess` on Windows, `/proc` on Linux; on macOS by the app name only): known ones (`KNOWN`: Minecraft Java Edition → `{ exe: 'minecraft', name: 'Minecraft' }`), else the main class or `-jar` file as key and the window title as name.
- Site lists (`prefs.lists`): one per application, matched on the normalized executable (`{ exe }`; `{ title }` if unknown; `null` = general list, used when nothing is detected, always present and not removable), created only when the first site is added; named after the application (`foregroundApp().name`, else the window title; lists named after a window title are renamed once the app name is known, except predefined ones, `renameContextList`). The current list is the one chosen by hand (`prefs.pinnedList`) or else the one of the app the overlay was opened over (`foregroundApp()`, sent by `main.js` at every show). The old single list (`sites`) is migrated to the general list, without the sites of the predefined lists.
- `bookmarks.js`: bookmark import (read-only) and export. Sources: one per browser profile, from the folders given by `platform.bookmarkStores()` (Chromium browsers: `Bookmarks` JSON + profile names from `Local State`, Opera also with its Speed Dials and other `custom_root` folders; Firefox and derivatives: `profiles.ini` + `places.sqlite`, read from a temporary copy with its `-wal` through `node:sqlite`, so it works with Firefox open), or an HTML file in the Netscape format chosen with the system dialog (`bookmarks:file`; the overlay does not hide on blur while it is open, `fileDialogOpen`). Returns a tree of folders (`root`: bar/menu/other/mobile) and http(s) bookmarks. The page imports from the add dialog (`openAddDialog`): from the "+" in the bar with the Address and Bookmarks tabs, into the current list; from "Import bookmarks…" in the Bookmarks section at the end of the Home (`home`), bookmarks only, into a list chosen in the dialog (the current one at first): tree with checkboxes, search, addresses already in the list not selectable, selection by address (`addSites` skips duplicates). Export (`openExportDialog`, "Export bookmarks…" in the same section): the same tree component (`treePicker`) with one folder per list and its sites, all selected at first, plus an "all bookmarks" checkbox; saved by `main.js` (`bookmarks:export`, system save dialog) as a Netscape HTML file with one folder per list (`toHtml`).
- `lists/`: predefined lists shipped with the app (`index.json` maps executables to files, see `lists/README.md`); loaded automatically the first time the overlay is opened over an app that has no list yet (`prefs.presetsApplied`), then only offered on the Home if that list is removed.
- `index.html`: Home with all site lists (current one first, others collapsible; edit sites, use a list, remove a list), tabs of the current list (one `<webview>` per site, created when its tab is first opened; the site's name follows the title of its page while the page is on the site's address, ignoring query and fragment (`samePage`), e.g. a renamed Google document; the tab shows the page's favicon with the same rule (`page-favicon-updated`, `setSiteIcon`), downloaded by `main.js` (`site:icon`, `fetchIcon`: the overlay page is cross-site for the site, so `Cross-Origin-Resource-Policy` or hotlink protection would block an `<img>` there) and kept in the prefs as a data: URL (`site.icon`, its address in `site.iconSrc`), reset when the address changes, taken over by Pin; pages not in use, i.e. all but the active tab of the visible overlay (`win:visible` sent by `main.js`), are each closed after some minutes without use, whatever their list, 5–60: `settings.unloadAfter` (until 1.0 there were two delays, the current list's `unloadCurrentAfter` is migrated to it), `sweepPages`; or by hand from the Settings page, memory section (first the app's own processes: interface, main process, GPU, other processes; then, set apart, the processes of the pages grouped by list, each group with its total and a "Close" for all its pages, closed at first, opened and closed by clicking its row like the lists on the Home (`memoryExpanded`), Browse and processes shared by pages of different lists as single rows; each part sorted by memory): "Close" on each page's row (pages sharing a process are closed together) and "Close all pages", `closePages`; a closed page loads again from the last address visited (`lastUrls`, kept in memory only); a list always opens on its last tab (`activeTab`: a site id, `':home'`, `':settings'` or `':browse'`), its page reopened if it was closed, `showCurrentList`; except when it is chosen or restored by hand from the Home ("Use", `pinned-restore`): then the Home stays shown; tabs and Home site rows reordered by dragging, `makeSortable`), free browsing tab right after the Home (`BROWSE`, one for all lists, always present: address field, also for searches (`addressOrSearch`: an address when it has a scheme or starts with a host, otherwise a search with `settings.searchEngine`, one of `SEARCH_ENGINES` (names validated in `main.js`, addresses in the page) or `'custom'` with `settings.searchCustom`, an address with `%s`), start page `settings.browseStart` (field with an "×" that empties it), empty = none (the empty page then shows as an example ("Try for example: …") the name of the current list's application, not for the general list, as a link that searches it with the chosen engine, `renderBrowseSuggest`; the "back to the start page" button then closes the page and shows the empty one again); "Pin" (also in the sites' tabs) turns the page, with its history, into a new tab of the current list (after the site's tab, at the end from the free browsing tab), `pinPage`; when its page is the address of one of the current list's tabs (`pageMatch`: ignoring http/https, `www.`, the final `/` and the fragment; also after in-page navigations), that tab is highlighted and Pin is disabled (in a site's tab, Pin is also disabled on the tab's own address); the pages it opens in a new tab stay in it); "…" button right of the address (sites' tabs and Browse, `#nav-more`) with a menu of operations on the active page (`#nav-menu`, closed by a click elsewhere, Esc, a tab change, the overlay hiding): delete the cookies of its domain, after a confirmation (`cookieDomain`: the host without `www.`; `main.js` `cookies:clear` removes from the shared default session the cookies of that domain, its subdomains and its parent domains, then the page reloads; the log has the tab and the count, never the domain); settings (including window opacity, `settings.opacity`, applied by the page via CSS when `state.platform.opacity === 'css'`, natively by `main.js` otherwise, hidden when `'none'`; accent color, `settings.accent`, a name from the predefined palette: names validated in `main.js` (`ACCENTS`), colors in the page (`ACCENT_COLORS`, CSS variables `--accent`/`--accent-text`; the fixed tabs, Home, Browse and Settings, have their text in the accent color); fixed tabs with icon and name or icon only, `settings.fixedTabs` (`'labels'`/`'icons'`, class `fixed-icons` on body); next to the title, the app version, `app.getVersion()` sent by `main.js`, and the GitHub link, `REPO_URL`, opened in the system browser).
- `locales/*.json`: UI texts, one file per language (code = file name); read by `main.js` and passed to the page. Language: user setting, else first available system language, else English.
- `preload.js`: IPC bridge between the page and the main process.
- `chrome-hints.js`: session preload (`registerPreloadScript`) of the site pages, see the Client Hints above.
- Build: `npm run dist` (electron-builder, packages for the current OS, unsigned) into `dist/`; `dist:win` (NSIS installer + portable), `dist:store` (unsigned AppX for the Microsoft Store, signed by the Store on submission; tiles in `build/appx/`; built by the manual `store.yml` workflow; the Store version's `userData` is redirected under `%LOCALAPPDATA%\Packages\…`), `dist:linux` (AppImage, built on Linux); `dist:mac` (DMG arm64 + x64, ad-hoc signed, built on macOS; icon `build/icon-mac.png`, 512 px).

## Branches and releases

- `release/<major.minor>` (now `release/1.0`): fixes and small polish for the version being released. Release tags (`v1.0.0-beta.2`, `v1.0.0`, `v1.0.1`…) are created here; the release workflow runs on any `v*` tag, whatever the branch.
- `main`: development of the next version (now 1.1; bookmark import/export, unloading of unused pages and the Browse tab, first planned for 1.1, were moved into 1.0 during its beta). New features go on `feature/<name>` branches from `main`, merged back into `main`.
- A fix for the released version is always made on the release branch, then the release branch is merged into `main` (`git merge release/1.0`); never merge `main` into a release branch or cherry-pick features into it. Only exception: while a version is still in beta (no stable tag yet), if the user decides that the features on `main` go into it, the release branch is moved forward to `main` (`git checkout release/1.0 && git merge --ff-only main`), only when the release branch has no commits missing from `main` (merge it into `main` first); then a new beta is tagged.
- Before working, check which branch is checked out and whether the change is a fix (release branch) or a feature (`main`/feature branch); ask if unclear.
- When the next version is ready for beta, create `release/<next>` from `main`.
